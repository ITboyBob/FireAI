# 文档读取规则

本文件定义代理如何从 [文档索引](./文档索引.md) 中选择最小且足够的上下文。根目录 `AGENTS.md` 是启动入口，本文件不重复环境、依赖、测试或 Git 强制规则。

## 新会话默认读取

1. 自动接收根目录 `AGENTS.md`。
2. 读取 `docs/system_meta/文档索引.md`，确认文档角色和权威边界。
3. 读取本文件，按当前任务扩展上下文。

默认集合到此结束。除非任务触发，不读取全部 `docs/`、历史设计或长实施计划。

## 按任务扩展

| 任务类型 | 应读取 | 通常不需要读取 |
| --- | --- | --- |
| 项目介绍、安装和运行 | `README.md`；涉及技术细节时再读工程技术标准 | PRD、历史计划 |
| 日常代码开发和缺陷修复 | 工程技术标准、相关代码与测试；涉及既定任务时先读实施计划总览，再读对应分卷 | 无关计划、一期历史资料 |
| 产品范围和产品验收 | 2.0 PRD；需要评估实现影响时再读工程技术标准和当前实施计划 | 一期历史设计 |
| 架构和技术策略 | 工程技术标准、相关专项设计；需要决策原因时读对应 ADR | 无关实施计划 |
| 2.0 主线执行 | 2.0 PRD、2.0 实施计划总览、当前任务分卷、工程技术标准 | 其他实施计划分卷、一期实施计划 |
| 增量法规导入 | Append-Only 实施计划总览、当前任务分卷、工程技术标准、相关代码与测试 | 无关分卷、2.0 前端专项设计 |
| 法规摄取能力或里程碑状态 | 能力路线图；需要解释目标结构时再读总体架构入口 | 具体分卷、一期历史资料 |
| 多格式法规摄取架构 | 能力路线图、总体架构入口；再按任务读取组件、分类与提取、正文边界或质量门禁专项；追溯入口决策时读 ADR | 无关实施计划、一期历史资料 |
| 多格式法规摄取实施 | 能力路线图、当前里程碑计划总览与分卷、对应专项设计和工程技术标准 | 其他里程碑分卷、一期历史资料 |
| W-S1 端到端摄取实施 | 能力路线图、总体架构入口、W-S1 实施计划总览、当前任务分卷和对应专项设计；涉及 textutil 或标准库契约时读运行时契约核验记录；涉及提交时读取 Append-Only 总览和当前代码 | 其他 W-S1 分卷、PDF/OCR 分卷和一期历史资料 |
| S2 边界能力或 W-S2 组合验收 | 能力路线图、S2/W-S2 计划总览、当前任务分卷、正文边界专项和质量门禁专项；核对真实样本时读 todo 评估基线；涉及提交时再读 Append-Only 总览和当前代码 | 其他 W-S2 分卷、S3/PDF/OCR 计划和一期历史资料 |
| todo 文件分类或提取 | 多格式摄取总设计、分类与提取专项；核对真实样本时再读 todo 评估基线 | 正文边界和批次状态全文 |
| 法规正文边界或附件排除 | 多格式摄取总设计、正文边界专项；核对真实样本时再读 todo 评估基线 | 提取器细节、无关历史计划 |
| 多格式质量门禁或批次状态 | 多格式摄取总设计、质量门禁专项；涉及提交时再读 Append-Only 总览和对应分卷 | 无关提取器细节 |
| todo 全量真实验收 | 能力路线图、覆盖目标策略组合的当前里程碑验收分卷、todo 评估基线、质量门禁专项、相关代码与测试；按失败类型补读对应专项 | 一期历史资料、无关在线链路文档 |
| NDJSON 状态流 | NDJSON 状态流设计、工程技术标准、相关实现和测试 | 增量导入计划 |
| 法规摄取当前进度和阻塞排查 | 能力路线图、对应实施计划、Git 记录、当前代码和真实运行结果 | 从历史叙事或计划完成度推测当前状态 |
| 其他当前进度和阻塞排查 | 对应实施计划、Git 记录、当前代码和真实运行结果 | 从历史叙事推测当前状态 |
| 文档维护 | 文档索引、本文件和目标文档；涉及权威变化时检查所有引用方 | 全量加载业务正文 |
| 文档系统维护 | `AGENTS.md`、文档索引、本文件、`README.md`、`CLAUDE.md` 与 `.claude/rules/` | 业务代码和生成物 |
| 历史追溯 | 仅加载索引中与问题直接相关的历史设计、历史计划或 ADR | 其他历史资料 |

## 不默认读取

- `docs/reference_material/` 中的历史设计和历史实施计划。
- `docs/reference_material/2026-06-28-todo-legal-corpus-assessment.md`，除非任务需要核对真实文件证据或验收基线。
- 当前任务不涉及的实施计划分卷。
- 与当前任务无关的实施计划、专项设计和 ADR。
- `data/`、`var/`、`.pytest_cache/`、模型缓存和其他生成物。
- `法律文本/` 中的原始法规全文；只有证据核验任务才按需读取具体文件。

## 冲突优先级

1. 用户当前明确指令。
2. 根目录 `AGENTS.md` 的仓库级执行规则。
3. 2.0 PRD 的产品目标、范围和产品验收。
4. `docs/architecture_or_strategy/工程技术标准.md` 的当前技术规则。
5. 在各自范围内生效的专项设计和 ADR。
6. 当前实施计划中的任务步骤。
7. `README.md` 的项目入口说明。
8. 历史设计、历史计划和叙事性材料。

`CLAUDE.md` 与 `.claude/rules/` 只能补充工具使用方式，不得覆盖 `AGENTS.md`。`.claude/settings.json` 可以在运行时收紧工具权限；被权限阻止时应报告阻塞，但不能据此改写仓库政策。若同级文档冲突，先检查更新时间、适用范围和代码现状；仍无法判断时停止执行并请求用户决策。

## 维护要求

- 新增文档时，同时登记路径、角色、加载策略、读取时机和权威级别。
- 删除文档时，同时清理索引、读取规则、入口链接和正文引用。
- 文档达到 500 行前应按职责边界拆分，并为分卷建立短总览入口。
- 权威边界变化时，必须同步 `AGENTS.md`、本文件、README 以及受影响文档的权威声明。
- 不为单次任务创建长期记忆层，不把生成文档或个人叙事提升为运行时事实。
