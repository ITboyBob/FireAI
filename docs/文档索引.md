# 文档索引

本目录按 Harness Engineering / Context Engineering 的“稳定上下文、计划、状态隔离”原则组织。

## 文档分层

- [设计文档](./plans/2026-03-28-fire-law-rag-design.md)
  - 只保留稳定上下文：目标、范围、架构、目录结构、模块职责、约束与测试策略。
  - 不记录滚动执行状态。

- [产品需求文档（PRD）](./plans/2026-04-11-fire-qa-system-2.0-prd.md)
  - 记录经确认的产品问题、目标用户、功能范围、用户故事、实现决策、测试决策与非本期范围。
  - 用于把“已经谈清楚的方向”固定成后续设计细化和实施计划的输入。

- [实施计划](./plans/2026-03-28-fire-law-rag-implementation.md)
  - 只保留任务拆分、步骤、验收方式与执行约束。
  - 不记录滚动执行状态。

- [实施计划（消防问答系统 2.0）](./plans/2026-04-11-fire-qa-system-2.0-implementation.md)
  - 记录 2.0 会话层、多轮上下文、会话 API、前端双栏界面的逐任务实施步骤。
  - 可直接作为当前工作区的批次执行计划使用。

- [架构决策记录（ADR）](./adr/2026-03-28-normalization-and-chunking-refactor.md)
  - 记录关键取舍：为什么选这个方案、拒绝了什么替代方案、门禁为什么存在。
  - 不承担滚动状态，也不代替实施步骤。

- [技术债记录](./debts/2026-03-29-chunk-builder-enum-red-test-debt.md)
  - 记录已经识别、已知存在、但当前主线选择暂缓处理的工程债务。
  - 用于解释“为什么当前不修、临时如何放行、未来怎样解除”。

- [项目状态](./status.md)
  - 本仓库唯一的执行状态文档。
  - 所有任务进展、运行环境、验证结果和当前阻塞点只在这里更新。

## 使用规则

- 需要理解系统为什么这样设计时，先看设计文档。
- 需要理解“这期产品到底要解决什么问题、做哪些能力、不做哪些能力”时，读 PRD。
- 需要理解“当前消防问答系统 2.0 主线做到哪一层、下一步按什么任务继续推进”时，优先看 2.0 实施计划与项目状态，而不是回到旧的单轮实施计划。
- 需要理解“为什么选这个重构方案、为什么任务被门禁拦住、为什么不能采用其他方案”时，读 ADR。
- 需要理解“为什么某条已知红测当前不修、为什么它不应继续阻塞主线放行”时，读技术债记录。
- 需要按旧单轮 RAG 主线推进实现时，看旧实施计划；需要按 2.0 会话系统主线推进实现时，看 2.0 实施计划。
- 需要确认“做到哪一步、在哪个环境验证过、当前卡在哪里”时，只看项目状态文档。

## 新会话读取顺序

本节用于给人和代理解释“为什么这样读”，真正具有仓库级约束力的规则以根目录 `AGENTS.md` 为准。

1. 先读本文件，理解文档系统的分层和入口。
2. 再读 [项目状态](./status.md)，确认当前执行状态。
3. 若任务涉及产品目标、功能范围、用户故事或本期边界，先读 [产品需求文档（PRD）](./plans/2026-04-11-fire-qa-system-2.0-prd.md)。
4. 若任务涉及架构和约束，再读 [设计文档](./plans/2026-03-28-fire-law-rag-design.md)。
5. 若任务涉及方案取舍、任务门禁、重构原因，再读 [架构决策记录（ADR）](./adr/2026-03-28-normalization-and-chunking-refactor.md)。
6. 若任务涉及已知技术债、临时放行策略或“为什么一条红测当前不算主线阻塞”，再读 [技术债记录](./debts/2026-03-29-chunk-builder-enum-red-test-debt.md)。
7. 若任务涉及继续实现或验收，再读对应实施计划；旧单轮主线见 [fire-law-rag-implementation](./plans/2026-03-28-fire-law-rag-implementation.md)，消防问答系统 2.0 主线见 [fire-qa-system-2.0-implementation](./plans/2026-04-11-fire-qa-system-2.0-implementation.md)，当前重构门禁见 [normalization-and-chunking-refactor](./plans/2026-03-28-normalization-and-chunking-refactor.md)。

## 读取原则

- 只按任务需要加载文档，避免把所有文档一次性塞进上下文。
- `docs/status.md` 是唯一滚动状态源，不得从设计文档和实施计划中推测最新进度。
- 设计文档回答“系统应该怎样”，ADR 回答“为什么选这个方案”，实施计划回答“接下来怎么做”，状态文档回答“现在做到哪里”。
- PRD 回答“为什么做这件事、本期做什么、不做什么、怎样才算满足产品需求”。
- 技术债记录回答“哪些问题已知存在但当前选择不修、为什么不修、怎样临时放行、未来怎样解除”。
