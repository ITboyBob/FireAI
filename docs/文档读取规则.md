# 文档读取规则

本文件定义代理如何从 [文档索引](./文档索引.md) 中选择最小且足够的上下文。根目录 `AGENTS.md` 是启动入口，本文件不重复环境、依赖、测试或 Git 强制规则。

## 新会话默认读取

1. 自动接收根目录 `AGENTS.md`。
2. 读取 `docs/文档索引.md`，确认文档角色和权威边界。
3. 读取本文件，按当前任务扩展上下文。

默认集合到此结束。除非任务触发，不读取全部 `docs/`、历史设计或长实施计划。

## 按任务扩展

| 任务类型 | 应读取 | 通常不需要读取 |
| --- | --- | --- |
| 项目介绍、安装和运行 | `README.md`；涉及技术细节时再读 `docs/工程技术标准.md` | PRD、历史计划 |
| 日常代码开发和缺陷修复 | `docs/工程技术标准.md`、相关代码与测试；涉及既定任务时再读对应实施计划 | 无关计划、一期历史资料 |
| 产品范围和产品验收 | 2.0 PRD；需要评估实现影响时再读工程技术标准和当前实施计划 | 一期历史设计 |
| 架构和技术策略 | 工程技术标准、相关专项设计；需要决策原因时读对应 ADR | 无关实施计划 |
| 2.0 主线执行 | 2.0 PRD、2.0 实施计划、工程技术标准 | 一期实施计划 |
| 增量法规导入 | Append-Only 实施计划、工程技术标准、相关代码与测试 | 2.0 前端专项设计 |
| NDJSON 状态流 | NDJSON 状态流设计、工程技术标准、相关实现和测试 | 增量导入计划 |
| 当前进度和阻塞排查 | 对应实施计划、Git 记录、当前代码和真实运行结果 | 从历史叙事推测当前状态 |
| 文档维护 | 文档索引、本文件和目标文档；涉及权威变化时检查所有引用方 | 全量加载业务正文 |
| 文档系统维护 | `AGENTS.md`、文档索引、本文件、`README.md`、`CLAUDE.md` 与 `.claude/rules/` | 业务代码和生成物 |
| 历史追溯 | 仅加载索引中与问题直接相关的历史设计、历史计划或 ADR | 其他历史资料 |

## 不默认读取

- `docs/plans/2026-03-28-*` 历史设计和历史实施计划。
- 与当前任务无关的实施计划、专项设计和 ADR。
- `data/`、`var/`、`.pytest_cache/`、模型缓存和其他生成物。
- `法律文本/` 中的原始法规全文；只有证据核验任务才按需读取具体文件。

## 冲突优先级

1. 用户当前明确指令。
2. 根目录 `AGENTS.md` 的仓库级执行规则。
3. 2.0 PRD 的产品目标、范围和产品验收。
4. `docs/工程技术标准.md` 的当前技术规则。
5. 在各自范围内生效的专项设计和 ADR。
6. 当前实施计划中的任务步骤。
7. `README.md` 的项目入口说明。
8. 历史设计、历史计划和叙事性材料。

`CLAUDE.md` 与 `.claude/rules/` 只能补充工具使用方式，不得覆盖 `AGENTS.md`。`.claude/settings.json` 可以在运行时收紧工具权限；被权限阻止时应报告阻塞，但不能据此改写仓库政策。若同级文档冲突，先检查更新时间、适用范围和代码现状；仍无法判断时停止执行并请求用户决策。

## 维护要求

- 新增文档时，同时登记路径、角色、加载策略、读取时机和权威级别。
- 删除文档时，同时清理索引、读取规则、入口链接和正文引用。
- 权威边界变化时，必须同步 `AGENTS.md`、本文件、README 以及受影响文档的权威声明。
- 不为单次任务创建长期记忆层，不把生成文档或个人叙事提升为运行时事实。
