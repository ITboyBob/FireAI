# 离线文档处理技术栈合理性分析报告

审计范围为 `法律文本/todo/` 与 `新法规文件/` 的 24 份实质文档（排除 `.DS_Store`），当前探针将其识别为 11 份可读 Word、4 份常规文本 PDF、6 份需 OCR 的 PDF，以及 3 份正文可读但带复制限制的文本 PDF 候选。

## 第一部分：现有“文档分类和处理模型”的缺陷

1. 当前代码把所有 PDF 都直接标记为 PX，因此探针已经能区分的 PT、PS 和“可提取但需权限复核”的文件仍全部被挡在自动处理流程外。
2. 现有文件判定过度依赖“能否抽到字符”，而两份 CFF/CMap 异常标准即使分别抽出约 7.1 万和 3.9 万个非空字符，中文占比仍不足 1%，所以会把乱码误当正文。
3. 扫描型 PDF 判定只看顶层图片覆盖率，会漏掉分块扫描图、Form/XObject，或某一解析器读坏但另一渲染器可打开的文件，使实际可 OCR 的文档继续停留在 Unknown。
4. 内容分类只认识“第…条”，因此 8 份采用 `1`、`1.1`、`1.1.1` 编号的技术或职业标准，以及被 OCR 插入空格的条文，都无法稳定进入 S1—S3。
5. 模型默认一份源文件只有一个目标正文且 Word 只扁平转成纯文本，因而无法安全表达“通知加两份指南”“办法加评分表”和含表格附件的 Word 文件。

## 第二部分：新方案只新增的内容

1. 新增“来源与访问状态”维度，分开记录文件是否完整、是否加密、是否限制复制和来源是否可信，避免把业务权限问题误判成技术上不可提取。
2. 新增“候选处理链”维度，为同一文件记录原生提取、备用解析器、页面渲染和 OCR 的有序回退路线，因为本批次同时存在乱码文本层、损坏索引和纯扫描三类异常。
3. 新增“逻辑目标”维度，把一个源文件表达为 0 到多份带角色和页码范围的候选正文，因为通知、正文、指南和评分表不应被当作一篇语料。
4. 新增“正文结构模式”维度，在 S1—S4 之外记录法规条文、数字编号标准、通知正文和表格主导等模式，因为它们需要不同的边界识别与切块方式。
5. 新增“质量与放行证据”维度，统一记录可读性、页覆盖率、阅读顺序、OCR 置信度、表格保真度和边界置信度，因为“工具执行成功”不等于“可进入 RAG”。

## 第三部分：新方案的完整模型

1. “来源层”先冻结文件摘要，并交叉核对签名、MIME、扩展名、解析状态、访问限制和来源可信度，输出可处理、需复核或拒绝三种结论。
2. “提取层”保留 W/PT/PS/PX 轴，用 Word 结构读取处理 W、用逐页原生文本处理 PT、用 PDFium 渲染加中文 OCR 处理 PS，并让 PX 只承接所有批准路线都无法安全解释的文件。
3. “目标层”把每份来源拆成 0 到多份逻辑目标，为每份目标记录正文、通知、附件、表格或说明等角色、页码边界、版本关系和去重关系。
4. “内容层”继续对每份逻辑目标使用 S1—S4 判断前后材料风险，同时用正文结构模式选择“第…条”、数字分级标题、通知段落或表格结构的专用边界与切块规则。
5. “质量层”依据文本可读性、页级覆盖、阅读顺序、OCR 置信度、表格保真度和边界置信度给出 ready、review_required 或 failed，且保存工具版本、指标与样本证据以便复现。

## 新增探针依赖名单（附录）

| 依赖项 | 作用 |
| --- | --- |
| `pypdf 6.17.0` | 检查页数、加密状态、原生文字层和基础 PDF 结构。 |
| `pdfplumber 0.11.10` | 检查逐页文本块、图片对象、坐标和表格候选。 |
| `pypdfium2 5.13.0` | 将页面稳定渲染为图像，并验证 `pypdf` 无法读取的 PDF 是否仍可处理。 |
| `Tesseract 5.5.3` | 在本机离线执行 OCR，当前环境同时具备 `chi_sim`、`eng` 和 `osd` 语言数据。 |
| `pytesseract 0.3.13` | 从 Python 调用 Tesseract，并读取文字、位置和置信度。 |
| `fonttools 4.59.0` | 复核 CFF 字体编码；安装后乱码仍存在，证明两份异常标准需要 OCR 回退而不是继续补字体解析库。 |
| `Pillow 12.3.0` | 作为 PDF 页面图像与 OCR 引擎之间的图像对象桥接层，本轮由 Conda 将环境版本更新到该版本。 |
| `pdfminer.six 20260107` | 作为 `pdfplumber` 的底层文本与版面解析组件，由 Conda 自动引入。 |
| `Leptonica 1.87.0` | 作为 Tesseract 的底层图像处理组件，由 Conda 自动引入。 |

其余字体、图片编解码、加密和网络基础库均由 Conda 作为上述组件的传递依赖自动解析，不应被当作独立的文档分类维度；本轮未安装 OpenCV 或 PyMuPDF。
